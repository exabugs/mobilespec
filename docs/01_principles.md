# 原則

## 目的

1. AI が効率的に動作できること
2. 人間向けドキュメントを生成するソースとして効率的に使えること

## SSOT の 4 原則

- **S1 宣言は 1 回。** 同じ事実を 2 か所に書かない。他のレイヤーは名前で参照する
- **S2 導けるものは書かない。** 画面 ID（ファイル名）、終端、遷移の起動のしかた、ja の文言、遷移図、索引は生成物
- **S3 ロジックは L4 だけ。** 演算子を持つ式は `conditions[].expr` にだけ書く。L2 / L3 は名前の参照だけ
- **S4 純度はスキーマと検証で強制する。** 違反は error で、正しい置き場所を案内する

## 構造が正

- 仕様に無い画面・遷移・API 呼び出しを、実装で作らない
- URL・HTTP メソッドを仕様に書かない。L4 は OpenAPI の `operationId` と `args` で接続する
- 構造が矛盾しているときは、推測せず診断に従う

## 診断は 2 段階

| level | 意味                            |
| ----- | ------------------------------- |
| error | 実装不能（CI が失敗する）       |
| info  | 状況の可視化（CI は落とさない） |

warning は使わない。
